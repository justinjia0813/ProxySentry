# ProxySentry 设计说明

状态：用户已批准，首版已实现并通过自动化验收

日期：2026-08-27

目标平台：Apple Silicon、macOS 26.5.2
主要适配对象：Clash Verge Rev 5.0.7；Clash Verge Rev 2.4.7 仅作兼容回退

## 1. 用户可见结果

ProxySentry 是一个仅在菜单栏运行的个人网络诊断工具。它持续观察本机网络和代理链路，并用一个紧凑图标回答两个问题：

1. 当前是直连、代理正常，还是网络异常？
2. 代理异常时，证据更支持本机网络、本地代理配置，还是机场或节点出口故障？

点击图标后显示主结论、最近检测时间、关键证据和三个操作：立即复检、打开 Clash、复制诊断摘要。状态变化稳定后发送一次系统通知，恢复后发送一次恢复通知。

## 2. 成功标准

- 菜单栏始终只占一个图标宽度；颜色之外同时使用不同符号表达状态。
- 无代理且直连可用时显示蓝色直连状态；代理出口成功时显示绿色代理状态。
- 只有本机网络、系统代理、本地代理端口和 Clash 内核均有正常证据，而多个代理出口目标连续两轮失败时，才显示红色“疑似机场或节点故障”。
- 证据不足时缩小结论，不把无法定位的故障归因给机场。
- Clash 控制接口不可用时，通用网络诊断继续工作。
- 相同故障不重复通知；状态必须连续两轮一致才切换。
- 首次启动默认尝试启用登录后自动启动，并可在展开面板中关闭；首版没有独立设置页。若本地构建缺少有效代码签名，则明确显示该功能不可用，不绕过系统机制。
- 不修改系统代理、Clash 配置、节点或订阅，不自动执行修复。
- 在五分钟正常空闲采样中没有忙循环、没有重叠检测，平均处理器占用低于 1%。

## 3. 范围

### 首版包含

- macOS 原生菜单栏应用。
- 系统网络路径、域名解析、直连出口、系统代理、本地代理端口和代理出口检测。
- Clash Verge Rev 的只读增强信息：内核版本、当前节点或代理组、已有延迟信息。
- 五种主状态、展开面板、系统通知、登录时启动、诊断摘要复制。
- 正常与异常防抖、超时、取消和探针失效降级。

### 首版不包含

- 自动切换节点、重启 Clash、修改系统代理或执行网络修复。
- 订阅管理、流量统计、测速、连接日志浏览或历史趋势。
- 独立设置窗口、自动更新、代码签名、公证或公开分发。
- Surge、V2Ray 等客户端的专有控制接口；它们仍可使用通用诊断。
- 虚拟网卡模式下的强制直连绕过。该模式只能报告“直连路径不可独立判断”。

## 4. 技术方向

应用使用 Swift、SwiftUI 和 AppKit 编写，不引入第三方依赖：

- AppKit 创建原生菜单栏项目和弹出面板。
- SwiftUI 构建面板内容。
- Network framework 监听系统网络路径并执行本地端口探测。
- 系统网络会话分别执行显式直连和显式代理请求。
- UserNotifications 发送状态变化通知。
- ServiceManagement 管理登录时启动。

应用不启用 App Sandbox，以便个人本地构建读取 Clash 的应用支持目录和 Unix 域套接字；它不申请管理员权限、不监听对外端口，也不执行辅助进程。

## 5. 组件与数据流

### 5.1 NetworkMonitor

负责 15 秒定时触发、网络路径变化触发、手动复检和异常快速复检。任何时刻最多有一轮诊断；新触发在已有诊断结束后合并为一次补充诊断。

### 5.2 ProbeRunner

按固定顺序执行探针，并把每项结果统一为：

- `success`：成功，并带耗时和非敏感摘要。
- `failure`：明确失败，并带错误类别。
- `timeout`：三秒内无结果。
- `unavailable`：当前模式下无法可靠检测。

探针只产生事实，不决定最终状态。

### 5.3 DiagnosisClassifier

接收一轮探针结果，按固定优先级计算唯一主状态、用户可见说明和证据列表。它是纯逻辑，不直接访问网络或文件。

### 5.4 ClashReader

检测 Clash Verge Rev 进程与应用支持目录，只读取必要的顶层配置项。优先通过本机 Unix 域套接字访问只读 Application Programming Interface（API，应用程序编程接口），即程序之间交换状态的约定接口。

内部控制接口不被 Clash Verge Rev 承诺为稳定的第三方接口，因此它只提供增强信息。访问失败、响应变化或密钥不可读时返回 `unavailable`，不得改变通用诊断结果。

### 5.5 StateDebouncer

保存当前展示状态和候选状态。候选状态连续出现两轮才提交；恢复同样需要两轮。只在提交后的状态类别发生变化时通知。

### 5.6 MenuBarPresenter

把已提交状态映射为菜单栏图标、弹出面板和通知。它不参与诊断判断。

数据流为：

`触发器 → ProbeRunner → DiagnosisClassifier → StateDebouncer → MenuBarPresenter`

ClashReader 只向 ProbeRunner 补充 Clash 证据。

## 6. 探针设计

每轮诊断依次获取：

1. 系统是否存在可用网络路径，以及当前接口类型。
2. Domain Name System（DNS，域名系统）解析是否成功；域名系统负责把域名转换为网络地址。
3. 绕过应用层系统代理的 Hypertext Transfer Protocol Secure（HTTPS，超文本传输安全协议）请求是否成功；这种请求用于验证加密直连出口。
4. 系统代理是否启用、代理类型、主机和端口是否完整。
5. 本地代理端口能否建立连接。
6. 明确通过该本地代理发送的 HTTPS 请求是否成功。
7. Clash 进程、内核版本、当前代理组或节点以及已有延迟信息是否可读。

直连和代理出口各使用至少两个不同运营方的轻量目标。请求不带设备标识、查询参数或业务数据；任一目标成功即可证明该路径可用。只有所有目标都失败，才认为该路径本轮失败。

不主动对所有节点测速。Clash 已有延迟时直接展示，没有则显示“延迟未知”，避免每 15 秒制造额外代理流量。

## 7. 状态判定

| 状态 | 图标语义 | 证据门槛 | 展开面板主结论 |
| --- | --- | --- | --- |
| 绿色 | 勾号 | 代理路径被配置或 Clash 虚拟网卡已启用，且代理出口成功 | 代理工作正常 |
| 蓝色 | 直连箭头 | 系统代理未启用、无 Clash 虚拟网卡，且直连出口成功 | 未启用代理，直连网络正常 |
| 黄色 | 感叹号 | 基础网络可用，但系统代理指向不可达端口，或 Clash 本地进程、配置与端口状态不一致 | 本机代理配置异常 |
| 红色 | 叉号 | 直连成功、本地代理端口可达、Clash 内核正常，但多个代理出口目标连续两轮全部失败 | 疑似机场或节点故障 |
| 灰色 | 斜线 | 系统网络路径不可用，或直连和代理同时失败，或虚拟网卡模式使故障无法可靠隔离 | 网络不可用或暂时无法定位 |

判定优先规则：

1. 代理出口成功始终优先显示绿色。
2. 无代理且直连成功显示蓝色。
3. 基础网络有正常证据但本地代理链路断裂显示黄色。
4. 红色必须满足全部归因门槛；缺少任何一项都不得显示红色。
5. 其余无法可靠归因的失败显示灰色，并在详情中说明最小缺口。

## 8. 监测、超时与通知

- 正常情况下每 15 秒执行一轮轻量诊断。
- 系统网络路径、无线连接或系统代理发生变化时立即触发。
- 首次异常两秒后复检；两轮结果一致才提交新状态。
- 单项探针三秒超时；一轮诊断最长八秒，超时后取消未完成任务。
- 应用唤醒或电脑从睡眠恢复时立即重测，不补跑睡眠期间的定时任务。
- 相同状态不重复通知。已提交状态发生变化时通知一次，恢复绿色或蓝色时通知一次。
- 通知正文只包含主结论和一条最关键证据，不包含节点订阅信息或密钥。

## 9. 界面

### 菜单栏

仅显示一个紧凑图标：

- 绿色勾号：代理正常。
- 蓝色箭头：直连正常。
- 黄色感叹号：本机代理异常。
- 红色叉号：疑似机场或节点异常。
- 灰色斜线：网络不可用或无法定位。

颜色和符号同时变化，避免只靠颜色传达状态。

### 展开面板

从上到下显示：

1. 主状态、最近检测时间和是否正在复检。
2. Clash 摘要；不可用时显示“Clash 详情不可用”，不显示错误堆栈。
3. 失败或不可判断的证据，优先排列。
4. 已通过的证据。
5. 立即复检、打开 Clash、复制诊断摘要。
6. “登录时启动”开关和退出应用。

诊断摘要包含时间、主状态、每项探针的成功或失败、耗时和归因说明；不包含控制密钥、配置全文、订阅地址或完整系统日志。

## 10. 错误处理与隐私

- 配置文件缺失、格式变化、权限不足和控制接口响应变化都降级为 Clash 增强信息不可用。
- 网络错误按解析失败、连接拒绝、连接超时、加密握手失败和代理认证失败分类；用户界面使用直白中文，不展示底层错误码。
- 应用不写诊断历史、不采集分析数据、不上传日志。
- 内存中只保留当前状态、候选状态和最近一轮探针结果；退出后清除。
- 控制密钥只在发起本机只读请求时短暂使用，不写入界面、剪贴板、日志或偏好设置。
- “打开 Clash”只启动已安装的 Clash Verge Rev 5.0.7；找不到时显示非阻塞提示。

## 11. 验证设计

### 自动验证

1. 用表驱动测试覆盖五种主状态、红色全部门槛、证据不足降级、虚拟网卡不可独立判断和代理成功优先级。
2. 用可控时钟测试连续两轮提交、相同状态不通知、恢复通知和快速抖动。
3. 用系统提供的网络请求替身模拟成功、连接拒绝、解析失败和超时，不访问真实机场。
4. 用固定文本样本验证只读取 Clash 必要顶层配置项，并确保控制密钥不会进入诊断模型或摘要。
5. 用改变字段和缺失字段的样本验证 Clash 接口失效时通用诊断仍返回结果。

### 本机验收

在当前 Mac 上验证：

1. 关闭系统代理且直连正常时显示蓝色。
2. Clash 正常、系统代理启用且出口可用时显示绿色，并尽力展示当前节点。
3. 保持系统代理启用但退出 Clash 时显示黄色。
4. 通过测试替身注入“本地链路正常、全部代理出口失败”时显示红色，不修改真实 Clash 配置。
5. 断开无线网络时显示灰色。
6. 每种状态连续保持一分钟，确认没有重复通知。
7. 手动检查浅色与深色菜单栏、刘海两侧空间、面板裁切、文字完整性和键盘可达性。

## 12. 完成边界

满足成功标准和自动验证、本机验收后，首版即完成。任何自动修复、节点控制、历史记录、更多代理客户端专有适配、公开发布或可配置探针目标均为后续独立需求，不在本次实现中预留抽象或空接口。
